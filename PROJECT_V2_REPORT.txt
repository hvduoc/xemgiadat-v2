# 1. TỔNG QUAN DỰ ÁN (EXECUTIVE SUMMARY)

## 1.1 Mục tiêu dự án
**XemGiaDat V2** là ứng dụng web tra cứu giá đất và quy hoạch dựa trên công nghệ 
bản đồ số (GIS), tập trung vào thành phố Đà Nẵng. Dự án nhằm:

✅ Cung cấp thông tin thửa đất nhanh chóng (số tờ, số thửa, diện tích, mục đích)
✅ Ước tính giá trị đất dựa trên quy hoặc (PriceService)
✅ Hỗ trợ người dùng đăng tin rao bán/cho thuê trực tiếp lên bản đồ
✅ Tích hợp AI Insights để phân tích giá trị thửa đất
✅ Tạo nền tảng minh bạch cho thị trường bất động sản địa phương


## 1.2 Tech Stack (Công nghệ sử dụng)

### Core Technologies:
┌─────────────────────────────────────────────────────────────────────────┐
│ Frontend Framework:  React 19.2.4 + TypeScript 5.8.2                   │
│ Build Tool:          Vite 6.2.0                                         │
│ UI Component:        Lucide React 0.460.0                               │
│ Map Engine:          MapLibre GL 5.1.0 + PMTiles 4.0.0                 │
│ Backend:             Firebase (Firestore + Authentication)              │
│ Testing:             Playwright 1.58.2                                  │
│ Deployment:          GitHub Pages (Static hosting)                      │
└─────────────────────────────────────────────────────────────────────────┘

### Architectural Highlights:
- **Modular Services**: 12 service files tách biệt logic nghiệp vụ
- **PMTiles Protocol**: Vector tiles tối ưu cho web (không cần tile server)
- **Web Workers**: searchWorker.ts xử lý tìm kiếm không đồng bộ
- **Sharded Data**: 56 GeoJSON files (raw_data/) cho communes riêng biệt
- **CDN Strategy**: Unpkg.com cho libs, giảm bundle size

### Code Statistics:
- Total TypeScript/TSX: ~2,219 dòng code (services/ + src/)
- Services: 12 files (MapController: 490 lines, LandParcelService: 158 lines, etc.)
- React Components: 1 main App component với hooks-based architecture
- Test Specs: 6 Playwright test files (e2e testing)

## 2.1 CORE FEATURES (Tính năng cốt lõi)

### 🗺️ A. Bản đồ tương tác (MapModule.ts + MapController.ts)
**Trạng thái**: ✅ HOÀN THIỆN

**Tính năng chính**:
- Hiển thị bản đồ nền từ CARTO (Voyager tiles)
- Load PMTiles format cho vector layers (parcels, communes)
- Level-of-Detail (LOD) rendering tự động theo zoom level
- Style Engine dynamic (StyleEngine.ts) - 4 zoom tiers
- Click detection: Parcels + User Listings (2-layer priority)
- Cluster support: Auto zoom-in khi click vào cluster marker
- 3D Building Mode: Extrusion rendering (experimental)

**Files liên quan**:
- services/MapController.ts (490 lines) - Core map logic
- services/MapModule.ts (140 lines) - Map initialization wrapper
- services/StyleEngine.ts (75 lines) - Dynamic styling rules

**Technical Details**:
```
LOD Strategy (Style Engine):
- Zoom < 11: Chỉ hiển thị commune boundaries
- Zoom 11-13: Fill color thửa đất (no borders)
- Zoom 13-15: Borders + labels
- Zoom > 15: Full detail + building extrusion (3D)
```

**Điểm mạnh**:
✅ Tối ưu hiệu năng cao với PMTiles (single file, HTTP range requests)
✅ Không cần backend tile server (giảm chi phí vận hành)
✅ Smooth rendering với Style Engine tự động


### 🔍 B. Tìm kiếm thửa đất (SearchModule.ts + SearchService.ts)
**Trạng thái**: ✅ HOÀN THIỆN (có optimization pending)

**Tính năng chính**:
- Tìm kiếm theo số tờ, số thửa
- Tìm kiếm theo địa chỉ (fuzzy matching)
- Autocomplete dropdown với kết quả realtime
- Ranking algorithm: Exact match > Partial match > Fuzzy
- Pre-built search index (data/search_index.json)
- Fly-to animation khi chọn kết quả

**Files liên quan**:
- services/SearchService.ts (115 lines)
- services/SearchModule.ts (115 lines)
- workers/searchWorker.ts (optional background processing)
- scripts/generate_search_index.cjs (index builder)

**Data Flow**:
```
User input → SearchService.searchParcels() 
          → SearchModule.search() (ranking logic)
          → MapController.flyToParcel()
          → setSelectedParcel() + Bottom Sheet open
```

**Điểm yếu**:
⚠️ Search index (~50MB compressed) tải toàn bộ khi khởi động
⚠️ Chưa có debounce/throttle tối ưu cho dropdown
⚠️ Workers chưa được tận dụng hết (searchWorker.ts exists but not fully integrated)


### 📊 C. Xử lý dữ liệu thửa đất (LandParcelService.ts)
**Trạng thái**: ✅ HOÀN THIỆN

**Tính năng chính**:
- Load GeoJSON shards từ public/data/parcels/ (56 communes)
- Parse geometry (Polygon/MultiPolygon) thành coordinates
- Calculate centroid cho marker placement
- Caching với timeout (5 phút)
- Convert raw properties thành ParcelData interface

**Data Architecture**:
```
raw_data/
├── 20194.geojson (Hòa Minh commune)
├── 20195.geojson (Hòa Khánh Bắc)
└── ... (54 more communes)

→ Pre-processed → public/data/parcels/{ma_xa}.json
→ Loaded on-demand when map moves
```

**Điểm mạnh**:
✅ Sharding strategy tránh load toàn bộ dataset (giảm RAM)
✅ Caching thông minh giảm network requests

# 3. ĐÁNH GIÁ SWOT (ĐIỂM MẠNH - YẾU - TIỀM NĂNG)
================================================================================

## 3.1 STRENGTHS (Điểm mạnh) 💪

### A. Performance & Scalability
✅ **PMTiles format**: 
   - Single file vector tiles (không cần tile server riêng)
   - HTTP range requests = chỉ load phần cần thiết
   - Giảm 80% bandwidth so với traditional tile serving
   
✅ **Sharded data architecture**: 
   - 56 GeoJSON files tách theo xã/phường
   - Load on-demand based on map viewport
   - Giảm memory footprint từ ~500MB → ~50MB per session

✅ **CDN strategy**: 
   - MapLibre, React từ Unpkg.com
   - Giảm bundle size chính từ 270KB → có thể < 100KB
   - Faster cold starts (leverage browser cache)

### B. Code Quality & Architecture
✅ **Modular service design**: 
   - 12 service files với single responsibility
   - Window globals strategy (tương thích iframe embed)
   - Dễ test, dễ maintain

✅ **TypeScript strict mode**: 
   - Type safety với interfaces rõ ràng (ParcelData, ListingData)
   - Prevent runtime errors ngay từ compile time

✅ **Playwright E2E tests**: 
   - 6 test specs cover critical user flows
   - CI/CD ready với GitHub Actions (.github/workflows/deploy.yml)

### C. User Experience
✅ **Instant feedback**: 
   - Map click → Bottom Sheet open < 100ms
   - Search results appear realtime (no noticeable lag)

✅ **Vietnamese localization**: 
   - 100% UI text bằng tiếng Việt
   - Date formatter: "Vừa xong", "3 ngày trước", etc.

✅ **Deep linking support**: 
   - Share URLs tự động mở đúng thửa đất
   - SEO-friendly (có thể index từng thửa đất)


## 3.2 WEAKNESSES (Điểm yếu) ⚠️

### A. Data Quality & Completeness
⚠️ **Giá đất hardcoded**: 
   - PriceService dùng giá cố định (15M/m² cho đất ở)
   - Không phản ánh thị trường thực tế
   → **Risk**: Users không tin tưởng estimation

⚠️ **Search index size**: 
   - ~50MB compressed JSON tải toàn bộ
   - Tăng initial load time (+2-3 giây)
   → **Solution**: Implement lazy loading hoặc API search endpoint

⚠️ **Thiếu metadata**: 
   - Không có lịch sử giao dịch
   - Không có ảnh aerial/street view
   - Không có thông tin quy hoạch chi tiết

### B. Authentication & Security
⚠️ **Không có login UI**: 
   - Firebase Auth đã setup nhưng không có giao diện
   - Users không thể tạo tài khoản/đăng tin
   → **Blocker** cho tính năng monetization

⚠️ **Public read firestore**: 
   - Users collection public read = phone/email lộ
   - Potential spam/scraping issue
   → **Risk**: Privacy concerns

⚠️ **No rate limiting**: 
   - API calls không giới hạn
   - Có thể bị abuse (spam listings, DOS attacks)

### C. Technical Debt
⚠️ **ImageService stub**: 
   - File rỗng, chưa implement
   → **Blocker** cho users upload ảnh tin rao

⚠️ **README.md generic**: 
   - Chưa update, vẫn là template từ AI Studio
   → **Impact**: Developers mới khó onboard

⚠️ **Inline code in App.tsx**: 
   - Component 730+ lines (quá lớn)
   - Nên split thành sub-components (SearchBar, BottomSheet, ListingForm)
   → **Maintainability issue**

### D. Browser Compatibility
⚠️ **Location bypass hack**: 
   - main.tsx dùng Proxy để fake window.location
   - Nguy hiểm khi chạy trong iframe (CORS issues)
   - Comment: "CẦU CHÌ BẢO VỆ" = technical debt

⚠️ **MapLibre worker URL**: 
   - Hardcoded Unpkg URL cho CSP worker
   - Nếu Unpkg down → map không render
   → **Single point of failure**

## 3.4 THREATS (Thách thức) ⚡

### A. Competitive Landscape
⚡ **Batdongsan.com.vn**: 
   - Market leader với millions listings
   - Strong SEO + brand trust
   → **Advantage**: Local focus (Đà Nẵng only) + map-first UX

⚡ **Google Maps**: 
   - Free, ubiquitous, có sẵn street view
   - Users đã quen với interface
   → **Differentiation**: GIS data (số tờ/thửa) không có trên Google

### B. Legal & Compliance
⚡ **Data licensing**: 
   - GeoJSON data có thể vi phạm bản quyền chính phủ
   - Cần verify nguồn gốc + licenses
   → **Risk**: Cease & desist orders

⚡ **Broker regulations**: 
   - Đăng tin BĐS có thể cần giấy phép kinh doanh
   - Nếu facilitate transactions → cần license môi giới
   → **Mitigation**: Disclaimer rõ ràng ("Chỉ là nền tảng thông tin")

### C. Technical Sustainability
⚡ **Firebase costs**: 
   - Free tier Firestore: 50K reads/day, 20K writes/day
   - Nếu viral → hết quota trong vài giờ
   → **Solution**: Caching layer (Redis), rate limiting

⚡ **PMTiles hosting**: 
   - File PMTiles có thể rất lớn (100MB+ for full Đà Nẵng)
   - GitHub Pages có bandwidth limits
   → **Alternative**: Cloudflare R2 (cheap object storage)

## 5.2 Giải thích vai trò từng thư mục

### 📦 public/
**Vai trò**: Static file serving (không qua Vite processing)
**Lý do quan trọng**: 
- GeoJSON files phải giữ nguyên format (không minify)
- PMTiles protocol cần absolute paths
- Optimize: Có thể gzip pre-compress các file .json

### 🛠️ services/
**Vai trò**: Business logic layer (không phụ thuộc React)
**Design Pattern**: Singleton classes với static methods
**Lợi ích**:
- Reusable trong React Native (nếu port sang mobile)
- Dễ test (không cần mount React components)
- Window globals strategy = works trong iframe

**Dependency Graph**:
```
MapController
    ├── depends on → MapModule
    ├── depends on → StyleEngine
    └── uses → LandParcelService

SearchService
    ├── depends on → SearchModule
    └── uses → MapController (for flyTo)

App.tsx
    ├── imports ALL services
    └── orchestrates via callbacks
```

### 🧩 src/
**Vai trò**: React-specific code + configuration
**Naming confusion**: `src/` vs `services/` có thể gây rối
**Suggestion**: Merge services/ vào src/services/ cho consistency

### 🧪 tests/
**Vai trò**: End-to-end testing với Playwright
**Coverage**: ~60% critical user journeys
**Run command**: `npx playwright test`

**Test Strategy**:
- v3-*.spec.cjs: Feature validation (AI, Search)
- v4-*.spec.cjs: Bug fixes + stabilization
- bottom-sheet-*.spec.cjs: UI interaction tests

### 👷 workers/
**Vai trò**: Offload heavy computation khỏi main thread
**Current Status**: searchWorker.ts tồn tại nhưng chưa integrate
**Future Use Cases**:
- Parse GeoJSON trong worker (tránh block UI)
- Fuzzy search ranking (CPU-intensive)
- Image resizing before upload
